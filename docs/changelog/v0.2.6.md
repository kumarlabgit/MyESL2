# v0.2.6 — 2026-06-19

## New — `taskfile` command for running any task from a YAML control file
A new top-level command, `myesl2 taskfile <control.yaml> [overrides...]`, runs any of the existing tasks from a single YAML file instead of a long argv. The YAML must carry a `task_type:` key naming one of `train`, `evaluate`, `drphylo`, `aim`, `psc`, `visualize`, `encode-sizes`, or `info`; every other key maps to a CLI flag with the leading `--` stripped and hyphens preserved (so `feature-normalize: zscore` is the YAML form of `--feature-normalize zscore`). Positional arguments are given named keys (`list_path`, `hypothesis_path`, `output_dir`, etc.); boolean flags are YAML booleans, multi-value flags are YAML sequences, and repeatable `--param key=value` flags are expressed as a YAML mapping under `param:`. Any CLI flag passed after the YAML path overrides the matching YAML value and prints `[Warning] taskfile override: key=yaml -> cli` to stderr so the conflict is visible. A per-task-type allowed-key whitelist rejects keys that don't apply to the selected `task_type` (e.g. `feature-normalize: zscore` under a `task_type: psc` errors out before any work begins). Internally, `main.cpp`'s per-command argv loops have been lifted into `run_train` / `run_evaluate` / `run_drphylo` / `run_aim` / `run_psc` / `run_visualize` / `run_encode_sizes` / `run_info` helpers, and `taskfile` synthesizes argv from the merged YAML + CLI keys and dispatches into the same helpers — so every validation, default, and error path that direct CLI invocation goes through is reused unchanged. fkYAML v0.4.2 is vendored as a single-header parser under `include/third_party/`.

## New — `--feature-normalize` for column-wise scaling of numeric input
`train`, `drphylo`, and `aim` now accept `--feature-normalize <mode>` (numeric input only) to apply a column-wise transform to the assembled feature matrix immediately after class balancing and before the solver sees it, addressing the case where input columns have very different magnitudes and L1/L2 regularization would otherwise implicitly weight large-magnitude columns more. Four modes are recognized:

- **`none`** — no transform; output is byte-identical to prior versions.
- **`center`** — subtract per-column mean (mean-shifting).
- **`zscore`** — subtract per-column mean and divide by per-column standard deviation, the standard auto-scaling that brings every column to unit variance.
- **`slep`** — subtract per-column mean and divide by `sqrt(sum(x²)/N)` per column, reproducing the SLEP Matlab package's `opts.nFlag=1` column normalization in `mcLeastR.m`, `sgLeastR.m`, and `overlapping_LeastR.m`, where the RMS denominator is computed on the original column (i.e. before centering). Provided for users replicating SLEP results.

For `--datatype numeric` the default is **`slep`** — raw numeric feature columns commonly differ in magnitude by orders of magnitude, and L1/L2 regularization on the un-normalized matrix would implicitly weight large-magnitude columns more heavily, so the SLEP-compatible normalization is on by default. Pass `--feature-normalize none` to opt out and reproduce the un-normalized prior behavior. For any non-numeric datatype the default is `none`, and the flag is rejected with a clear error if set explicitly (centering and scaling a one-hot-encoded FASTA matrix would silently corrupt the binary feature semantics).

Zero-scale columns (`|scale| ≤ 1e-10`) have their scale clamped to `1.0`, matching SLEP's `mcLeastR.m:153` guard against divide-by-zero on constant columns. Per-column statistics are computed in `double` for numerical stability and applied to the `arma::fmat` in `float`; the stats are computed *after* class balancing, so they reflect the matrix the solver actually sees rather than the pre-balancing input. The transform parameters are persisted to `<output_dir>/feature_normalization.txt` (TSV with columns `Label`, `Mean`, `Scale`, preceded by a `# mode=<mode>` header line) once per run — the file is a property of the encoded matrix and is identical across the whole lambda grid, so it is not duplicated under each `lambda_<N>/` subdirectory. `evaluate` reads this file when scoring (searched first as a sibling of `weights.txt`, then in the parent directory for `lambda_N/weights.txt` layouts) and applies the identical transform to new data before computing predictions; the persisted `Mean` and `Scale` values carry `double` precision so the replay matches the training-time transform exactly. Models trained before this release have no `feature_normalization.txt`, and `evaluate` silently falls back to the prior un-normalized scoring path when the file is absent — old models keep evaluating byte-for-byte unchanged.

## New — `--help` is now structured as an overview plus per-command pages
The single `print_usage` that dumped every flag for every command has been split into an overview page plus one detailed page per command. `myesl2` with no arguments (or `myesl2 --help`) prints a short overview listing the available commands with one-line descriptions; detailed help for a single command is reached via `myesl2 --help <cmd>` or `myesl2 <cmd> --help`. The same per-command page is also what gets printed when a command is invoked with too few positional arguments, so the user is shown the relevant flags rather than the previous wall of every command's flags.

## New — exemplar taskfiles, photosynthesis demo data, and a numeric one-hot example
One YAML per task type now ships under `examples/taskfiles/` (`train`, `train_overlapping`, `train_numeric`, `evaluate`, `drphylo`, `aim`, `psc`, `visualize`, `encode-sizes`, `info`) as runnable references for the `taskfile` command. Every key with a non-trivial default is set explicitly in each file so the YAML doubles as a documentation surface for its task surface — readers can see at a glance what `taskfile` accepts for each task type and what the defaults are. Inputs are sized for fast runs (10–500 Fungi alignments for the train/drphylo/aim exemplars; 67 chloroplast genes for PSC), and `evaluate` / `encode-sizes` / `info` / `visualize` use the outputs of their dependency taskfiles (documented in each file's header).

The photosynthesis PSC demo dataset is now vendored under `Photosynthesis_data/` (67 chloroplast FASTA alignments + the `photo_single_LC_matrix_species_groups.txt` contrast file) so `psc.yaml` is self-contained — no external `/claude_work/ESL-PSC/` paths required. A small one-hot encoded numeric example (`Fungi_data/numeric_onehot_10/`, 10 TSVs, 3.1 MB) and its list file `Fungi_data/aln_10_numeric.txt` are added for the `train_numeric` exemplar; larger derived numeric sets can be regenerated by users via the (untracked) helper script under `tools/`. Lists of 500 protein FASTAs (`Fungi_data/aln_500.txt`, `Fungi_data/aln_500_overlapping.txt`) are added for the train/drphylo/aim/evaluate exemplars and reference the existing tracked FASTAs in `Fungi_data/aln/`.

`run_visualize` now creates the SVG output's parent directory before writing, so `visualize.yaml` works against a fresh `examples/out/visualize/` without manual `mkdir`.

## Fix — UTF-16 list files (PowerShell `>` / `Out-File` redirection)
PowerShell's default redirection (`>`, `Out-File`) writes UTF-16 LE with a BOM, which `std::getline` reads as bytes with `\x00` between every character. Those embedded nulls were getting into `fs::path` strings and OS-level path operations were truncating at the first null, so the cache lookup collapsed to just the cache directory itself and every file failed with `"END_METADATA not found in: <cache_dir>/"` (the filename was invisible because the printed `std::string` truncated at its own null too). A new helper `pipeline_utils::read_text_file_utf8()` detects UTF-16 LE/BE and UTF-8 BOMs and decodes UTF-16 to UTF-8 (with surrogate-pair handling); ASCII / UTF-8 without a BOM passes through verbatim. The helper is wired through the list-file readers in `pipeline_preprocess`, `pipeline_encode` (encode + encode-sizes paths), and `pipeline_evaluate` (numeric + FASTA paths), so Windows users who pipe `Get-Content … > list.txt` to build a list file no longer have to remember to convert the encoding by hand.
