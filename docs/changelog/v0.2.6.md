# v0.2.6 — 2026-06-11

## New — `taskfile` command for running any task from a YAML control file
A new top-level command, `myesl2 taskfile <control.yaml> [overrides...]`, runs any of the existing tasks from a single YAML file instead of a long argv. The YAML must carry a `task_type:` key naming one of `train`, `evaluate`, `drphylo`, `aim`, `psc`, `visualize`, `encode-sizes`, or `info`; every other key maps to a CLI flag with the leading `--` stripped and hyphens preserved (so `feature-normalize: zscore` is the YAML form of `--feature-normalize zscore`). Positional arguments are given named keys (`list_path`, `hypothesis_path`, `output_dir`, etc.); boolean flags are YAML booleans, multi-value flags are YAML sequences, and repeatable `--param key=value` flags are expressed as a YAML mapping under `param:`. Any CLI flag passed after the YAML path overrides the matching YAML value and prints `[Warning] taskfile override: key=yaml -> cli` to stderr so the conflict is visible. A per-task-type allowed-key whitelist rejects keys that don't apply to the selected `task_type` (e.g. `feature-normalize: zscore` under a `task_type: psc` errors out before any work begins). Internally, `main.cpp`'s per-command argv loops have been lifted into `run_train` / `run_evaluate` / `run_drphylo` / `run_aim` / `run_psc` / `run_visualize` / `run_encode_sizes` / `run_info` helpers, and `taskfile` synthesizes argv from the merged YAML + CLI keys and dispatches into the same helpers — so every validation, default, and error path that direct CLI invocation goes through is reused unchanged. fkYAML v0.4.2 is vendored as a single-header parser under `include/third_party/`.

## New — `--feature-normalize` for column-wise scaling of numeric input
`train`, `drphylo`, and `aim` now accept `--feature-normalize <mode>` (numeric input only) to apply a column-wise transform to the assembled feature matrix immediately after class balancing and before the solver sees it, addressing the case where input columns have very different magnitudes and L1/L2 regularization would otherwise implicitly weight large-magnitude columns more. Four modes are recognized:

- **`none`** (default) — no transform; output is byte-identical to prior versions when the flag is omitted or set to `none`.
- **`center`** — subtract per-column mean (mean-shifting).
- **`zscore`** — subtract per-column mean and divide by per-column standard deviation, the standard auto-scaling that brings every column to unit variance.
- **`slep`** — subtract per-column mean and divide by `sqrt(sum(x²)/N)` per column, reproducing the SLEP Matlab package's `opts.nFlag=1` column normalization in `mcLeastR.m`, `sgLeastR.m`, and `overlapping_LeastR.m`, where the RMS denominator is computed on the original column (i.e. before centering). Provided for users replicating SLEP results.

Zero-scale columns (`|scale| ≤ 1e-10`) have their scale clamped to `1.0`, matching SLEP's `mcLeastR.m:153` guard against divide-by-zero on constant columns. Per-column statistics are computed in `double` for numerical stability and applied to the `arma::fmat` in `float`; the stats are computed *after* class balancing, so they reflect the matrix the solver actually sees rather than the pre-balancing input. The transform parameters are persisted to `<output_dir>/feature_normalization.txt` (TSV with columns `Label`, `Mean`, `Scale`, preceded by a `# mode=<mode>` header line) once per run — the file is a property of the encoded matrix and is identical across the whole lambda grid, so it is not duplicated under each `lambda_<N>/` subdirectory. `evaluate` reads this file when scoring (searched first as a sibling of `weights.txt`, then in the parent directory for `lambda_N/weights.txt` layouts) and applies the identical transform to new data before computing predictions; the persisted `Mean` and `Scale` values carry `double` precision so the replay matches the training-time transform exactly. Models trained before this release have no `feature_normalization.txt`, and `evaluate` silently falls back to the prior un-normalized scoring path when the file is absent — old models keep evaluating byte-for-byte unchanged. The flag is rejected with a clear error when `--datatype` is anything other than `numeric`, since centering and scaling a one-hot-encoded FASTA matrix would silently corrupt the binary feature semantics.
