# v0.2.4 — 2026-06-02

## Breaking — `SPS_SPP` output schema gains an SCP column
`SPS_SPP` output now contains five columns instead of four: an `SCP` column carrying the raw `expit(prediction)` score is appended, and the existing `SPP` value is clamped to non-negative (misclassified species previously emitted negative SPP values). Scripts that read this file by positional column index need to handle the extra trailing column; consumers that key off the header are unaffected. Golden test fixtures and `test/compare_golden.sh` are updated for the new layout.

## Breaking — solver method names renamed (old names still accepted with deprecation warning)
The logistic solvers are renamed for symmetry with the least-squares family:

- `sg_lasso` → `sg_lasso_logisticr`
- `ol_sg_lasso` → `ol_sg_lasso_logisticr`

Old names continue to resolve via `resolve_method_alias()` but emit a deprecation warning at parse time. Documentation, help text, internal class names, and method-string switches are updated to the new names. Existing trained models do not need to be retrained — only the `--method` CLI string changes.

## New — overlapping SG-Lasso with virtual expansion (`ol_sg_lasso_logisticr`)
New solver for overlapping feature groups. Internally the coefficient vector is virtually expanded to length `F` (one slot per (feature, group) membership pair) so the existing non-overlapping FISTA proximal operators (`altra_inplace`, `treeNorm_flat`) work directly. Matrix-vector products run BLAS on the physical `m × n` matrix with gather/scatter through the field index — zero extra matrix memory regardless of overlap percentage.

- Bit-for-bit identical to `sg_lasso_logisticr` on 0%-overlap inputs (IEEE 754: `0 + x = x`).
- Verified on overlapping inputs up to 197% expansion; benchmarks across 20–100% overlap on tall (`m=7164`) and wide (`n=6.2M`) datasets are recorded in `reports/ol_sg_lasso_benchmark.md`.

## New — overlapping least-squares solver (`ol_sg_lasso_leastr`)
Least-squares counterpart to `ol_sg_lasso_logisticr` using the same virtual-expansion gather/scatter path plus the simpler `leastr` FISTA loop (precomputed `A^T·y`, no class weights or intercept optimization). Bit-for-bit identical to `sg_lasso_leastr` on non-overlapping input.

## New — PSC accepts `ol_sg_lasso_{logisticr,leastr}` as overlapping methods
PSC's help text already advertised the virtual-expansion methods alongside `olsg_lasso_*`, but the runtime gate rejected them with `"Overlapping groups require --method olsg_lasso_logisticr or olsg_lasso_leastr"` before the solver ran. The allowlist (and error message) now match the help text.

## New — group-aware deconvolution for overlapping method results
For `ol_sg_lasso_logisticr` and `ol_sg_lasso_leastr`, aggregated scores are deconvoluted by ontology group so each group's contribution is tracked separately.

**Train** (per `lambda_<L>/`):
- `weights_grouped.txt` — label, weight, group index
- `gss_grouped.txt`, `pss_grouped.txt` — per (gene, group) significance scores
- `oss.txt` — ontology significance score (sum of `|weight|` per group)

**Train** (per `penalty_<N>/`, grid median):
- `gss_median_grouped.txt`, `pss_median_grouped.txt`, `oss_median.txt`

**Evaluate**:
- `*_gene_predictions.txt` unchanged (cross-group sum; backward compatible).
- `*_gene_predictions_grouped.txt` — one column per ontology group.
- `*_gene_predictions_by_gene.txt` — one column per (gene, group) pair.

**DrPhylo aggregation** extended to fold grouped prediction files through the same qualifying-model median logic used for the ungrouped files. `expanded.map` gains a `Group` column for `ol_sg_lasso` methods. Non-overlapping methods and all pre-existing files are unchanged.

## New — OSS output for `olsg_lasso_{logisticr,leastr}`
`compute_sig_scores` now emits `oss.txt` for the original dual-variable overlapping solvers. Each weight label is mapped to its group via `label_to_col` + `alg_table`; per-group sums of `|weight|` are the OSS values. `oss_median.txt` is generated when running a lambda grid.

## New — CV fold-assignment controls (`--cv-seed`, `--cv-assignments`)
Three additions to K-fold cross-validation in `train`, `drphylo`, and `aim`:

1. `cv_predictions.txt` gains a `Fold` column. The fold a sample was held out in was previously only derivable from row index via `i % nfolds` — and only if you knew that convention.

2. `--cv-seed N` (opt-in) shuffles samples with `std::mt19937(N)` before round-robin assignment. Default `cv_seed = -1` preserves the legacy unshuffled `i % nfolds` behavior so existing pipelines reproduce exactly. This fixes a latent class-balance issue when input is class-sorted (e.g. 84 fungal samples ordered `-1...-1, 1...1` previously produced wildly imbalanced folds; a seeded shuffle restores rough balance).

3. `--cv-assignments <file>` overrides both the seed and the round-robin. Loads a TSV with `SequenceID` and `Fold` columns. Header auto-detected when both names are present; without a header, the file is read as 2-column (`SequenceID\tFold`). A prior run's `cv_predictions.txt` can be passed directly — handy for holding the fold split fixed across lambda settings or solver methods. Every training sample must appear in the file (missing samples listed in the error); fold values outside `[0, nfolds-1]` are rejected with a clear message.

## New — accuracy and AUC in `evaluate`
The `evaluate` classification-metrics block now reports two additional values alongside `TP/TN/FP/FN/TPR/TNR/FPR/FNR`:

- **Accuracy** — `(TP + TN) / N`.
- **AUC** — Mann-Whitney rank-based with average-rank tie handling. Reports `N/A` / `NaN` when the hypothesis covers only one class (where AUC is undefined).

Both are echoed to stdout and written to `process_log.txt`.

## New — single-feature inputs accepted
Encoder sanity checks now permit datasets with exactly one feature column (numeric) or one distinct alignment position (FASTA); the previous minimum of two has been lowered to one. A single-feature input is mathematically valid for sparse regression and the downstream solvers handle `n=1` without issue.

## New — PSC `weights_ungrouped.tsv` for virtual-expansion methods
When `--dump-weights` is set and the active method is `ol_sg_lasso_*`, PSC now also emits `weights_ungrouped.tsv` alongside the existing aggregated `weights.tsv` inside each `[combo_N/][penalty_P/]lambda_L/` directory. The ungrouped file carries one row per non-zero expanded copy with a third `group` column, so duplicate feature labels are preserved with distinct group indices. The aggregated `weights.tsv` is unchanged.

## New — portable Linux release bundles `libquadmath.so.0`
The portable manylinux2014 build's `libgfortran.so.5` carries a `NEEDED` entry for `libquadmath.so.0` (the symbols haven't been absorbed by the older GCC in that container). SLURM worker nodes and other minimal Linux installs without `libquadmath` in a default search path previously failed to load `myesl2` with `libquadmath.so.0: cannot open shared object file`. The portable archive now ships `libquadmath` next to `libgfortran` so the runtime loader resolves it through `$ORIGIN`.

The standard Ubuntu archive gains a defensive `NEEDED`-check fallback that pulls `libquadmath` from the system GCC if any bundled library still references it. A no-op on current Ubuntu (where `libgfortran` absorbs `libquadmath`) but future-proofs the build if the toolchain splits them again.

## New — `.release-channel` marker file for channel autodetection
Source tarballs and zips downloaded from GitHub omit the `.git` directory, so the previous git-branch-based channel detection in `scripts/setup.sh` / `scripts/setup.ps1` silently fell through to the `main` default — meaning a user who downloaded the dev branch as a zip (rather than cloning) received main-channel binaries.

A new `.release-channel` file at the repo root carries the channel identifier in the source tree itself, so any extraction method preserves it. The setup scripts now consult, in order:

1. `--channel` / `-Channel` CLI flag
2. `.release-channel` file at repo root
3. `git rev-parse --abbrev-ref HEAD` (fallback for older checkouts)
4. `main` (default)

The existing `main|dev` allowlist at the end of channel selection still catches typos and CRLF line endings.

## Bug fix — PSC segfault with `ol_sg_lasso_*` methods
The virtual-expansion overlap solvers return a parameter vector of length `F` (one entry per expanded feature copy), not the original `n`. Downstream PSC code assumed `beta.size() == prep.feature_metas.size()` and crashed reading `feature_metas[j]` for `j ∈ [n, F)` during `gene_gss` aggregation. The `--dump-weights` path had the same OOB read, and `compute_prediction_scores` silently dropped the expanded weights. After `getParameters()` returns, expanded copies are now summed back into the original feature slot via the field array. Sum (not max) preserves the model's prediction because every expanded copy of feature `i` multiplies the same input column: `Σⱼ (βⱼ · xᵢ) = (Σⱼ βⱼ) · xᵢ`. Dual-variable `olsg_lasso_*` methods are unaffected (they already return `n`-length vectors).

## Bug fix — `evaluate` (numeric) sums duplicate feature labels
The numeric branch of `evaluate` parsed raw weights with `raw_weights[label] = w`, which silently last-wins-overwrote duplicate labels. Virtual-expansion overlap methods emit one row per expanded copy, so a numeric model trained with `ol_sg_lasso_logisticr` lost all but the last expanded weight per feature during evaluate. The assignment is now `+=` (the FASTA branch already accumulated correctly via `+=` in the scoring loop). `std::map<>::operator[]` zero-initializes on first access, so unique-label cases are unaffected.

## Bug fix — PSC `gene_gss` formula matches train
PSC's per-gene GSS was previously `|Σⱼ βⱼ|` over expanded copies (side effect of aggregating the solver output into original-feature space before taking `abs`). Train/drphylo/aim/adaptive's `compute_sig_scores_grouped` reports `Σⱼ |βⱼ|` — abs each expanded copy, then sum. The two formulas only diverge when expanded copies of a single original feature take opposite signs. PSC now iterates the un-aggregated solver output for `gene_gss` and `gene_selected_sites`, mapping expanded indices to original features via the field array. The signed-sum aggregation into `result.beta` is preserved for `dump-weights` and `compute_prediction_scores`, which still need `n`-length 1:1-with-`feature_metas` weights.

## New — white background on SVG visualizations
`write_svg` and `write_aim_svg` previously rendered with a transparent background, leaving the area outside the heatmap grid see-through when embedded against dark themes. A full-canvas white rect is now drawn under the heatmap so the page background never shows through.

## Documentation — `evaluate` positional args
The CLI help block and README description for `evaluate` are restructured to make the input/output roles of the two positional arguments explicit (mirroring the `train` help block), call out that `--hypothesis` is optional and only required when accuracy metrics are wanted, and correct the README's described output columns to match the actual TSV (`SequenceID`, `PredictedValue`, optional `TrueValue`).
