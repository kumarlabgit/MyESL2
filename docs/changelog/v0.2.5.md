# v0.2.5 — 2026-06-05

## New — auto-detect single FASTA / numeric file in place of a list or directory
When the alignment-input positional argument to `train`, `evaluate`, `drphylo`, `aim`, or `psc` (also `psc --alignments-list` and PSC's prediction directory) actually points to a single FASTA alignment or single tabular numeric file — rather than the expected list-of-paths file (or directory, for PSC) — the file is detected by inspecting its first non-whitespace byte (`>` = FASTA) or first non-empty line (contains `\t` = numeric). The pipeline transparently treats it as a 1-entry input and continues. A `[Warning]` is printed to stderr (deduped per canonical path across the preprocess / encode / evaluate phases of one run), and `preprocess` additionally logs `auto_detected_single_input` in `process_log.txt`. Previously these inputs failed downstream with misleading `Cannot open list file:` or `No alignments found in:` errors because the FASTA header line or numeric header row was parsed as a comma-separated list of paths. Real list files and directories are handled byte-for-byte unchanged when the detection is negative — the list-reading and directory-enumeration code paths remain the `else` branch.

## Bug fix — m-grid SVG excludes alignment-only species
In `--m-grid` mode (DrPhylo's positive-class-only view), species with `response == 0` were placed in the positive panel alongside species with `response > 0`. The intended semantics are "rows from the positively-labelled class only"; the m-grid branch now filters strictly on `response > 0`, excluding the alignment-only / unlabelled species that carry a sentinel zero response. Non-m-grid mode is unchanged (`response == 0` still appears in the positive panel there).

## Bug fix — SVG row labels show SPP, not raw `expit(pred)`
The per-species score appended to SVG row labels now uses the per-class normalized SPP that `write_sps_spp_file` writes to `eval_SPS_SPP.txt`, matching MyESL's `gene_contribution_visualizer.py`. Previously the label carried raw `expit(prediction)`, which disagreed numerically with the `SPP` column users were reading alongside the SVG. The normalization is computed over **all** species in the input — not just the visible post-`--species-limit` truncation rows — so the value for a given species does not drift when fewer rows are displayed.

## Behavior change — default `--gene-limit` and `--species-limit` lowered from 100 to 20
The auto-generated SVG heatmaps in `train`, `evaluate`, `drphylo`, and the standalone `visualize` command now default to 20 genes × 20 species. The previous 100×100 default produced cluttered, label-illegible SVGs for typical runs. Pass `--gene-limit 100 --species-limit 100` explicitly to restore the old default. Help text and README updated.

## Behavior change — DrPhylo default lambda grid
When none of `--lambda`, `--lambda-grid`, or `--lambda-file` is given, `drphylo` now uses `--lambda-grid 0.1,0.9,0.1 0.1,0.9,0.1` (an 81-cell sweep), matching original MyESL's DrPhylo default. The shared `train` default is unchanged; only the `drphylo` path picks up this default when no lambda flag is set.

## New — `evaluate` seeds species universe from the full list file
`evaluate` now reads the seq_ids from every input file in `list.txt` (not just the files the active model references) when populating `species_sums`, falling back to FASTA header lines (FASTA branch) or the PNF metadata + first-column scan (numeric branch) when caches are absent. Species the model doesn't reference contribute zero and emit the intercept in the prediction column. The motivation is DrPhylo aggregation: each lambda's model picks a different subset of alignments, but every lambda's `evaluate` now reports the same row set, so the aggregator can key by integer row index across the lambda grid. Plain (non-DrPhylo) `evaluate` runs see the same predictions for every species the model already referenced; species the model doesn't reference now appear with the intercept-only prediction instead of being silently absent.
